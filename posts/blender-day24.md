# Blender学習24日目｜腕と脚を左右対称にする

今日は、昨日まで片側だけだった腕と脚を左右対称に増やした。

ボーンにはBlenderの「対称化」、腕のメッシュにはミラーモディファイアー、分割式の脚メッシュには3Dカーソルを基準とした反転複製を使用した。

作業途中では、アーマチュアの原点が身体の中央からずれていることや、ミラーで作った右腕がボーンへ追従しない問題も見つかった。それぞれの原因を確認しながら、左右の関節を独立して動かせる状態まで仕上げた。

## 左右を表すボーン名へ変更

最初に、既存の腕と脚がキャラクター本人から見てどちら側にあるかを確認した。

画面のこちら側から見ると右側に見えるが、キャラクター本人から見れば左腕・左脚にあたる。そのため、既存のボーン名へ`.L`を追加した。

- `SH_Clavicle.L`
- `WP_UpperArm.L`
- `WP_Forearm.L`
- `SH_Thigh.L`
- `SH_Shin.L`
- `SH_Foot.L`

![既存の腕と脚のボーン名へ.Lを追加](/zelk96-studio/images/day24/01.png)

Blenderの`.L`と`.R`は画面を見る人ではなく、キャラクター本人を基準に付ける。リネーム後も腕と脚が正常に動くことを確認した。

## 対称化の前にアーマチュアの原点を確認

ボーンの対称化は、アーマチュアのローカルX座標`0`を中心に実行される。

ところが座標を確認すると、左上腕のヘッドXは`-1.5m`、左太もものヘッドXは`-1.85m`だったのに対し、身体中央にある`SH_Spine`のヘッドとテールのX座標はどちらも`-2.25m`になっていた。

さらに、`EL_Armature`オブジェクト自体のX座標は`4m`だった。以前は腕だけだったアーマチュアへ身体や脚を追加してきたため、アーマチュアの原点と現在の身体中央が一致していなかった。

![身体中央とアーマチュアの原点がずれていた状態](/zelk96-studio/images/day24/02.png)

このまま対称化すると、身体中央ではなく別の位置を基準に反対側のボーンが作られてしまう。

## アーマチュアの原点を身体中央へ移動

まず編集モードで`SH_Spine`を選択し、`Shift + S`から「カーソル → 選択物」を実行して3Dカーソルを身体中央へ移動した。

続いてオブジェクトモードへ戻り、`EL_Armature`を選択して「原点を設定 → 原点を3Dカーソルへ移動」を実行した。

![3Dカーソルを基準にアーマチュアの原点を修正](/zelk96-studio/images/day24/03.png)

修正後は`SH_Spine`のヘッドとテールのX座標がともに`0m`となった。原点だけを移動したため、ボーンやメッシュの見た目の位置はずれていない。

アーマチュアのオブジェクト座標はX`1.75m`へ変化したが、これは原点のワールド座標が身体中央へ移動した結果である。

## 左側のボーンを対称化

編集モードで`.L`を付けた6本のボーンだけを選択し、「アーマチュア → 対称化」を実行した。

中央にある`SH_Root`、`SH_Pelvis`、`SH_Spine`は左右へ複製する骨ではないため、選択から除外した。

対称化によって、反対側へ次のボーンが作成された。

- `SH_Clavicle.R`
- `WP_UpperArm.R`
- `WP_Forearm.R`
- `SH_Thigh.R`
- `SH_Shin.R`
- `SH_Foot.R`

![対称化で作成した右側の腕と脚のボーン](/zelk96-studio/images/day24/04.png)

`.L`と`.R`の名前も自動で対応し、親子関係やコンストレイントも反対側へ引き継がれた。

## 腕のメッシュをミラーで増やす

腕は上腕から前腕までがひとつながりの`EL_ArmMesh`になっているため、ミラーモディファイアーで反対側を作った。

設定は次のとおり。

- 座標軸：X
- ミラーオブジェクト：`EL_Armature`
- 「頂点グループ」を有効化
- ミラーモディファイアーをアーマチュアモディファイアーより上に配置

![ミラーモディファイアーで反対側の腕を表示](/zelk96-studio/images/day24/05.png)

ミラーオブジェクトを`EL_Armature`にしたことで、先ほど身体中央へ移動したアーマチュアの原点を対称面として利用できた。

モディファイアーの順番も重要で、今回は先に腕を左右へ複製し、その結果をアーマチュアで変形させる必要がある。

## 右腕用の頂点グループを追加

見た目は左右に腕が表示されたものの、最初は右腕のボーンを動かしてもメッシュが追従しなかった。

原因は、`EL_ArmMesh`に左腕用の頂点グループしか存在していなかったことだった。

そこで、既存の`.L`グループと対になる空の頂点グループを追加した。

- `WP_UpperArm.L`
- `WP_Forearm.L`
- `WP_UpperArm.R`
- `WP_Forearm.R`

![左右4つの頂点グループを用意した状態](/zelk96-studio/images/day24/06.png)

ミラーモディファイアーの「頂点グループ」が有効なら、`.L`と`.R`の名前を使って反対側のウェイトが対応付けられる。追加後は、左右の腕をそれぞれのボーンで独立して動かせるようになった。

## 左右の肘の回転方向を確認

ボーンの対称化では、肘の回転制限も左右に合わせて反転していた。

- `WP_Forearm.L`：ローカルZ軸のマイナス方向へ曲がる
- `WP_Forearm.R`：ローカルZ軸のプラス方向へ曲がる

左肘は`R → Z → Z → -90`、右肘は`R → Z → Z → 90`で胸側へ曲がった。どちらも反対方向、つまり身体の後ろ側へは曲がらないことを確認した。

![左右の肘を胸側へ曲げた動作確認](/zelk96-studio/images/day24/07.png)

同じポーズでも左右のボーンでは回転値の符号が逆になる。対称化は形だけでなく、左右に応じたボーンロールやコンストレイントの違いも処理してくれることが分かった。

## 脚のメッシュを反転複製

脚は腕と違い、太もも・すね・足がそれぞれ独立した硬いメッシュになっている。そこで左脚の3オブジェクトを複製して右脚を作った。

まず既存のメッシュへ`.L`を追加した。

- `SH_ThighMesh.L`
- `SH_ShinMesh.L`
- `SH_FootMesh.L`

3つをまとめて`Shift + D`で複製し、右クリックで移動をキャンセルした。その後、`Alt + P`から「親子関係をクリア（トランスフォームを維持）」を実行し、複製側を次の名前へ変更した。

- `SH_ThighMesh.R`
- `SH_ShinMesh.R`
- `SH_FootMesh.R`

![右脚用として複製した3つのメッシュ](/zelk96-studio/images/day24/08.png)

## 3Dカーソルをピボットにして反転

脚の3オブジェクトを身体中央の反対側へ移すため、トランスフォームピボットポイントを「3Dカーソル」、座標系を「グローバル」に変更した。

これは`Shift + S`でオブジェクトを3Dカーソルへ移動する操作とは異なる。3Dカーソルの位置は変えず、その場所を回転や拡縮の中心として利用する設定である。

右脚用の3メッシュを選択したまま、次の操作でX方向へ反転した。

```text
S → X → -1
```

![3Dカーソルを中心に右脚メッシュを反転](/zelk96-studio/images/day24/09.png)

反転後はスケールを適用し、負のXスケールを通常の`1`へ戻した。

## 右脚メッシュをボーン相対で親子付け

反転した右脚のメッシュを、それぞれ対応する右側のボーンへ「ボーン相対」で親子付けした。

| メッシュ | 親ボーン |
| --- | --- |
| `SH_ThighMesh.R` | `SH_Thigh.R` |
| `SH_ShinMesh.R` | `SH_Shin.R` |
| `SH_FootMesh.R` | `SH_Foot.R` |

![右脚の3メッシュを対応するボーンへ親子付け](/zelk96-studio/images/day24/10.png)

作業中、同じ右脚メッシュがアウトライナー内へ2つ表示されているように見えた。しかし片方は`EL_Armature`との親子関係、もう片方は所属コレクション内での表示だった。

どちらを選んでも同時にハイライトされ、名前にも`.001`が付いていなかったため、重複した別オブジェクトではなく同じオブジェクトだと確認できた。

## 右脚の動作を確認

最後にポーズモードで右脚の各ボーンを動かした。

- `SH_Thigh.R`を回すと、太ももから足までが追従する
- `SH_Shin.R`を回すと、すねと足が追従する
- `SH_Foot.R`は足首から独立して回転できる

![右脚の太ももと膝を曲げた動作確認](/zelk96-studio/images/day24/11.png)

太ももを大きく回すと骨盤との間に隙間が見えたが、左脚にも同じ隙間があった。今回は骨盤と太ももが別々の硬いメッシュなので、関節周辺が伸びたり滑らかに変形したりしないためである。

親子付けの失敗ではなく、分割式のブロックモデルとして正常な状態だった。

確認後は全ボーンの回転をリセットし、トランスフォームピボットポイントも「3Dカーソル」から普段使う「中点」へ戻した。

![左右の腕と脚がそろった完成状態](/zelk96-studio/images/day24/12.png)

## 現在のボーン階層

今日の作業を終えた時点で、ボーンの階層は次のようになった。

```text
SH_Root
└─ SH_Pelvis
   ├─ SH_Spine
   │  ├─ SH_Clavicle.L
   │  │  └─ WP_UpperArm.L
   │  │     └─ WP_Forearm.L
   │  └─ SH_Clavicle.R
   │     └─ WP_UpperArm.R
   │        └─ WP_Forearm.R
   ├─ SH_Thigh.L
   │  └─ SH_Shin.L
   │     └─ SH_Foot.L
   └─ SH_Thigh.R
      └─ SH_Shin.R
         └─ SH_Foot.R
```

中央の骨はひとつだけ残し、`SH_Pelvis`から左右の腕と脚へ枝分かれする全身リグになった。

## 今日の振り返り

今日は、片側だけだった腕と脚を左右へ展開した。

同じ左右対称化でも、ボーンには「対称化」、連続した腕メッシュにはミラーモディファイアー、分割された脚メッシュには3Dカーソルを中心とした反転複製を使った。対象の構造によって適した方法が異なることを実際に確認できた。

特に重要だったのは、左右対称化の中心がワールド原点ではなく、各オブジェクトの原点や指定したミラーオブジェクトによって決まる点だった。アーマチュアの原点が身体中央からずれたままでは、正しい位置に反対側を作れない。

また、腕の見た目をミラーするだけでは右側の変形は完成せず、`.L`と`.R`の頂点グループを対応させる必要があった。ボーン名、頂点グループ名、モディファイアーの設定が連携して初めて、左右の腕を独立して動かせる。

これまで作ってきた片側のリグが両側へ広がり、簡易的ながら全身の骨格らしい姿になった一日だった。
