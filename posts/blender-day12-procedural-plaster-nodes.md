# Blender学習 Day 12：ノードの流れを読み、プロシージャルな塗り壁を作る

Noiseの数値を可視化し、Scale・Color Ramp・Map Range・Bumpの役割を比較。金属以外への応用として、画像を使わない塗り壁を作りました。

<p class="post-meta">2026.08.24 · 黒暁</p>

## はじめに

Blender学習12日目。Day 11ではNoise Texture、Map Range、Color Ramp、Bumpを使って古びた真鍮を作ったが、指示どおり接続することはできても、それぞれの意味や情報の流れはまだ十分に理解できていなかった。

今回は新しいノードを大量に増やさず、同じノードの値を意図的に変えて見た目を比較した。最後は、その考え方を金属以外の素材へ応用し、画像を使わないプロシージャルな塗り壁を作った。

![色・粗さ・微細な凹凸を加えたDay 12の室内]({{ '/images/blender_day12_development_log/Day12_FinalRender.webp' | relative_url }})

## 今回の目標

- ノードを左から右へ流れる情報として読む
- Noise TextureのScaleが何を変えるか確認する
- Color Rampの位置と色差の役割を区別する
- Map Rangeで数値を素材に適した範囲へ制限する
- Bumpが作る疑似的な凹凸を理解する
- 金属以外の素材へプロシージャルノードを応用する

## 変化が見えないところから始まった

まず、奥の壁 `Wall_Back` が共有していた `MAT_Wall` を単独化し、`MAT_Wall_Plaster_Day12` として作業を始めた。

Principled BSDFの粗さを `0.800` から `0.150` へ下げたものの、見た目の違いはほとんど分からなかった。壁は平面で、正面に近い角度から均一に照らされている。強いハイライトや映り込みがないため、粗さを大きく変えても効果が見えにくい条件だった。

Noise Textureの係数を粗さへ直接接続しても、変化はやはり分かりにくかった。ここで、ノードが効いていないと決めつけるのではなく、まずNoiseが作っている情報そのものを色として表示してみることにした。

## Noiseの数値を白黒で可視化する

Texture Coordinateの「生成」をNoise Textureのベクトルへ接続し、Noiseの係数をColor Ramp経由でベースカラーへ渡した。

情報の流れは次のようになる。

`生成座標 → Noise Texture → Color Ramp → Base Color`

- Texture Coordinate：壁の各地点の位置を渡す
- Noise Texture：地点ごとに `0〜1` の数値を作る
- Color Ramp：数値を色へ変換する
- Principled BSDF：受け取った色を壁へ表示する

Color Rampの黒側を `0.450`、白側を `0.550` にすると、Noiseが作っていた小さな数値差が、はっきりした白黒模様として現れた。

![Noiseの数値をColor Rampで白黒へ変換した壁]({{ '/images/blender_day12_development_log/noise-color-ramp-scale3.webp' | relative_url }})

この時点で、Noise Textureは完成した色を出しているのではなく、素材の各地点で使える数値の地図を作っていると理解できた。

## Scaleは模様の細かさを変える

Noise TextureのScaleを `3` から `10` へ変更すると、大きな島のようだった模様が細かくなり、壁の中へ多く詰め込まれた。

![Noise TextureのScaleを10へ上げて細かくなった模様]({{ '/images/blender_day12_development_log/noise-scale10.webp' | relative_url }})

Scaleが変えるのは白黒の強さではなく、模様一つひとつの大きさだった。

| Scale | 模様の見え方 |
| --- | --- |
| 小さい | 大きな模様が少数できる |
| 大きい | 小さな模様が多数できる |

## Color Rampの位置と色差は別の役割

白側の位置を `0.550` から `0.750` へ動かすと、黒から白へ変化する範囲が広がった。中間の灰色が増え、真っ白な領域は減った。

一方、左右の印を近づけると中間色の範囲が狭まり、二色が急に切り替わる。実際に試すと、ほぼ均一な壁の中へ明るい斑点が点在する見た目になった。

ここで、Color Rampの「位置」と「色差」は別の役割だと分かった。

| 変えたいもの | 調整する項目 |
| --- | --- |
| 色の切り替わり方・分布 | 左右の位置 |
| 色ムラの強さ | 左右に設定した色の差 |

白黒で確認したあと、左をくすんだ壁色、右を明るい壁色へ変更した。最終的には左を `#CEC6C2`、右を `#DED7D1` とし、色差を小さくして自然な濃淡へ抑えた。

## Map Rangeで粗さを壁らしい範囲へ収める

Noise Textureの係数を粗さへ直接つなぐと、場所によって粗さが `0〜1` の全域を使う。これでは、完全に近いツルツルから完全なマットまで差が大きすぎる。

そこで、Noiseと粗さの間へMap Rangeを追加した。

`Noise Texture → Map Range → Roughness`

入力の `0〜1` を出力の `0.65〜0.90` へ変換し、壁全体をマットな範囲に保ちながら、わずかな反射ムラだけを残した。

| Noiseの値 | 粗さへ渡す値 |
| --- | --- |
| 0.0 | 0.65 |
| 0.5 | 0.775 |
| 1.0 | 0.90 |

![Map Rangeで粗さを0.65から0.90へ制限したノード]({{ '/images/blender_day12_development_log/map-range-roughness.webp' | relative_url }})

Color Rampが数値を色へ翻訳するのに対し、Map Rangeは数値を別の数値範囲へ翻訳するノードだと整理できた。

## 別のNoiseとBumpで微細な凹凸を作る

色ムラとは別に、Scale `60` の細かなNoise Textureを追加した。その係数をBumpの高さへ渡し、BumpのノーマルをPrincipled BSDFのノーマルへ接続した。

`細かなNoise → Bumpの高さ → Principled BSDFのNormal`

最初はBumpの強さ `0.120`、距離 `0.005` としたが、引いた画面では効果がほとんど分からなかった。そこで、学習用に強さ `1.000`、距離 `0.050` まで一時的に上げた。

![Bumpを極端に強くして凹凸の効果を確認した壁]({{ '/images/blender_day12_development_log/bump-exaggerated.webp' | relative_url }})

極端な値では、壁一面がはっきりとザラザラになった。Bumpはポリゴンを実際に変形させるのではなく、表面の向きを表すノーマルを変え、光の当たり方だけで凹凸があるように見せている。

- 壁の輪郭は変わらない
- ポリゴン数は増えない
- 横から光が当たる場所ほど凹凸が見えやすい

効果を確認したあと、最終値は強さ `0.250`、距離 `0.010` とした。完成レンダーでは、ドア右側など横から光が当たる場所で細かなザラつきを確認できた。

## 完成したノードの情報の流れ

![色・粗さ・凹凸を別々に制御した最終ノード]({{ '/images/blender_day12_development_log/final-plaster-nodes.webp' | relative_url }})

最終的なマテリアルでは、一つの座標から用途の異なる情報を作った。

| 情報の流れ | 役割 |
| --- | --- |
| 生成座標 → 大きなNoise → Color Ramp → Base Color | 壁のごく薄い色ムラ |
| 大きなNoise → Map Range → Roughness | `0.65〜0.90`の粗さムラ |
| 生成座標 → 細かなNoise → Bump → Normal | 微細な塗り壁の凹凸 |

完成したマテリアルは左の壁と天井にも割り当てた。共有マテリアルなので、以後の変更は3つへ同時に反映される。

## 画像テクスチャとプロシージャル素材の使い分け

作業中、「机へ木目を付けたときのように画像を貼る方が簡単で早いのでは」と感じた。これはそのとおりで、木目、錆、レンガ、革など複雑な実在素材は、良質なPBR画像を使う方が短時間でリアルになりやすい。

一方、プロシージャルノードには次の利点がある。

- 色や模様の大きさを数値で自由に変えられる
- 画像の解像度に依存しない
- 広い面で画像の繰り返しが目立ちにくい
- 既存のPBRへ粗さムラや汚れを追加できる

実制作では、どちらか一方に限定する必要はない。PBR画像を素材の主役にし、Noise TextureやColor Rampで変化を追加する組み合わせが実用的だと分かった。

## 振り返り

Day 12では、完成したノード構成をそのまま覚えるのではなく、変化が見えない状態から値を極端にし、各ノードが担当する見た目を切り分けた。

特に、凹凸を変えても色ムラは変わらないこと、Scaleを下げても色差そのものは弱くならないこと、Color Rampの位置を近づけると中間色が減って切り替わりが急になることを、実際の失敗と比較から確認できた。

最終的な色ムラは注意して見ないと分からないほど弱い。Color Rampを外して単色にしても成立するが、暗い照明では薄い濃淡が見えやすくなる。見た目へ貢献しないノードは必須ではなく、目的に合わせて残すか判断することも重要だと感じた。

Day 11では「指示どおり接続する」段階だったが、今回は途中から、色・粗さ・凹凸のどこを変えたいかによって触るノードを考えられるようになった。

## 次回

画像PBRとプロシージャルノードを組み合わせ、画像だけでは均一になりやすい部分へ粗さムラや汚れを追加する方法を試す。

今回と同じく、完成形を再現するだけでなく、接続する前後や極端な値を比較しながらノードを少しずつ読めるようにしていく。
