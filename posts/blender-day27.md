# Blender学習27日目｜アクションを分けて複数の動きを保存する

今日は、前日に混乱したキーフレーム操作を片腕だけで復習した後、アクションエディターを使って複数のアニメーションを個別に保存し、切り替える方法を学んだ。

前半は過去の学習内容と重複していることに途中で気づいたものの、そのまま終わらせず、後半では初めて「アクション」というアニメーションの管理単位に触れた。

また、使用中のBlender 5.2ではキーフレーム挿入メニューを開くキーが以前のバージョンと異なることも分かり、今後の操作に関わる重要な発見になった。

## 前日のアニメーションを削除して初期状態へ戻す

Day26では全身の複数ボーンにキーフレームを設定したため、どのキーがどの姿勢を記録しているのか分からなくなる場面があった。

今回は内容を整理するため、Day26のファイルを複製して`Day27.blend`として保存し、複製側のキーフレームをすべて削除した。

さらにポーズモードで全ボーンを選択し、次の操作でTポーズへ戻した。

- `Alt + G`：位置を初期化
- `Alt + R`：回転を初期化
- `Alt + S`：スケールを初期化

![キーフレームを削除してTポーズへ戻した状態](/zelk96-studio/images/day27/01.png)

タイムラインが空になり、全身も基準姿勢へ戻ったことを確認してから練習を始めた。

## 片方の上腕だけに回転キーを登録する

全身を一度に操作すると確認が難しくなるため、今回は`WP_UpperArm.L`だけを選択した。

記録する要素も位置・回転・スケールのすべてではなく、「回転」だけに限定した。これにより、ドープシートへ表示されるキーを減らし、どの操作がどのキーフレームを作ったのか確認しやすくした。

![左上腕のボーンだけを選択](/zelk96-studio/images/day27/02.png)

## Blender 5.2ではKキーで挿入メニューを開く

最初は`I`キーを押して「回転」を選択しようとしたが、選択メニューが表示されなかった。上部メニューの「ポーズ → アニメーション → キーフレームを挿入」を実行しても、回転を選ぶ一覧は出なかった。

調べた結果、Blender 5.2では役割が次のようになっていた。

| キー | Blender 5.2での役割 |
| --- | --- |
| `I` | 現在のキーイング設定を使って即座にキーフレームを挿入する |
| `K` | キーフレーム挿入メニューを開き、位置・回転・スケールなどを選ぶ |

3Dビュー上で`K`を押すと「キーフレーム挿入メニュー」が表示され、そこから「回転」を選択できた。

![Kキーで表示したキーフレーム挿入メニュー](/zelk96-studio/images/day27/03.png)

過去記事では旧バージョンの操作として`I`キーから種類を選んでいたが、現在使用しているBlender 5.2では`K`キーを使う必要がある。

## 腕を下げて停止し、元へ戻す

フレーム`1`でTポーズの回転を登録し、フレーム`20`で上腕を`R 55`により下げて、再び回転キーを登録した。

![フレーム20で片腕を下げた状態](/zelk96-studio/images/day27/04.png)

続いてフレーム`40`へ移動した。腕の角度は変えず、そのまま`K`から回転キーを登録した。

同じ角度をフレーム20と40の両方へ記録すると、その区間では値が変化しないため、腕が完全に停止する。

最後にフレーム`60`で`Alt + R`を使って回転を初期化し、Tポーズへ戻した状態を登録した。

| フレーム | 腕の状態 |
| ---: | --- |
| `1` | 水平なTポーズ |
| `20` | 腕を下げた姿勢 |
| `40` | フレーム20と同じ姿勢 |
| `60` | Tポーズへ戻る |

再生すると、フレーム1から20で腕を下げ、20から40で停止し、40から60で水平へ戻る動作になった。

## 補間方法を改めて比較する

4つのキーフレームを選択し、`T`キーから補間方法を切り替えて違いを確認した。

- ベジェ：動き始めと止まり際が滑らかになる
- リニア：一定の速度で動く
- 一定：途中を補間せず、次のキーで瞬間的に姿勢が変わる

これはDay17でも学習した内容だった。今回は片腕の回転だけに絞ったため、それぞれの違いを以前より確認しやすかった。

比較後は、自然な加速と減速が付くベジェへ戻した。

## キーフレームを1個だけ動かす練習

Day26では、複数ボーンのキーが同じフレームに重なり、1つだけ選択したつもりでも多くのキーを動かしてしまった。

今回はフレーム40のキーだけを選択し、`G 10`でフレーム50へ移動した。

その結果、停止区間がフレーム20〜40から20〜50へ延び、元の姿勢へ戻る区間は50〜60へ短くなった。

確認後は`G -10`でフレーム40へ戻した。キーを1つだけ選べば、姿勢を作り直さなくても動作のタイミングを調整できることを改めて確認した。

## 過去の内容と重複していることに気づく

ここまで進めたところで、キーフレーム、停止区間、補間方法の比較はDay17やDay26ですでに扱っていたことに気づいた。

前日の混乱を整理する復習としては役立ったが、Day27の新しい学習内容としては不足していた。そのため、片腕のアニメーションを素材として残し、ここから「アクション」の学習へ切り替えた。

## アクションエディターへ切り替える

ドープシート左上のモード選択を「アクションエディター」へ変更した。

Blenderのアクションは、キーフレームをひとまとまりにして保存する入れ物である。将来的には、同じキャラクターに対して次のような動作を個別に管理できる。

- `Idle`：待機
- `Walk`：歩行
- `Run`：走行
- `Attack`：攻撃

最初に作った「腕を下げて戻す動作」へ、`Arm_Lower_Test`という名前を付けた。

![最初の動作をArm_Lower_Testとして保存](/zelk96-studio/images/day27/05.png)

名前を付けることで、単なるタイムライン上のキーフレームではなく、何の動作を記録したアクションなのか判別しやすくなった。

## 盾アイコンでアクションを保存対象にする

アクション名の右側にある盾アイコンを有効にした。

アクションをアーマチュアから一時的に外すと、どこからも使用されていないデータになる。盾アイコンを有効にしておけば、現在選択されていないアクションも`.blend`ファイルへ保持できる。

その後、`×`で`Arm_Lower_Test`を現在の編集対象から外し、新しいアクションを作成した。

## Blender 5.2のアクションスロットを作成する

新しいアクションへ`Arm_Raise_Test`と名前を付けた。

Blender 5.2のアクションには、アニメーションさせる対象とキーフレームを結び付ける「スロット」がある。今回は新規スロットを作成し、対象として`EL_Armature`が表示されたことを確認した。

![新しいアクションとアーマチュア用スロットを作成](/zelk96-studio/images/day27/06.png)

最初は前のアクションで作った腕を下げた姿勢が3Dビューに残っていたが、アクションエディター内にキーフレームがないため、新しいアクション自体は空の状態だった。

フレーム1へ移動して`Alt + R`でTポーズへ戻し、`K`から回転キーを登録した。

## 腕を上げる別アクションを作成する

フレーム`20`では、最初に`R 70`を入力すると腕が下がったため、回転方向を反対にして`R -70`へ修正した。

![フレーム20で片腕を上げたArm_Raise_Test](/zelk96-studio/images/day27/07.png)

フレーム`40`では`Alt + R`で回転を初期化し、再びTポーズの回転キーを登録した。

これにより、`Arm_Raise_Test`は次のアニメーションになった。

```text
1：Tポーズ
↓
20：腕を上げる
↓
40：Tポーズへ戻る
```

こちらのアクションでも盾アイコンを有効にし、切り替え後も保存されるようにした。

## 2つのアクションを切り替える

アクションエディターのプルダウンから、次の2つを切り替えて再生した。

| アクション名 | 内容 |
| --- | --- |
| `Arm_Lower_Test` | 腕を下げ、停止してからTポーズへ戻る |
| `Arm_Raise_Test` | 腕を上げてからTポーズへ戻る |

![保存した2つのアクションを切り替えて確認](/zelk96-studio/images/day27/08.gif)

同じアーマチュアを使用しながら、選択するアクションによって異なるキーフレームと動作が呼び出された。

タイムラインへすべての動作を連続して並べなくても、用途ごとにアニメーションを分けて保存できることが分かった。ゲーム制作で待機、移動、攻撃などを切り替える際の基礎になりそうだ。

## 今日の振り返り

今日は前日の混乱を解消するため、ボーンを1本、記録項目を回転だけに限定してキーフレーム操作を復習した。

前半の内容はDay17やDay26と重複していたが、Blender 5.2では`I`ではなく`K`から挿入内容を選択すること、キーフレームを1個だけ選択してタイミングを変更することを整理できた。

後半では、初めてアクションエディターを使用した。アニメーションへ名前を付け、盾アイコンで保持し、アクションスロットを作成して、同じアーマチュアに2つの独立した動作を保存できた。

特に重要だったのは、アクションが単なる表示の切り替えではなく、それぞれ別のキーフレームを持つアニメーションデータだという点である。

今後は`Idle`、`Walk`、`Attack`など、用途の異なる全身アニメーションを作り、アクションとして整理する練習へつなげたい。
