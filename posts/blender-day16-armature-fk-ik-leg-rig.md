# Blender学習 Day 16：Armature・FK・IKでブロック人形の脚を動かす

ブロック人形へ脚のArmatureとIKを構築。軸を揃えた片脚で再検証し、膝が横へ曲がった原因をポール角度のずれまで切り分けて修正しました。

<p class="post-meta">2026.08.28 · 黒暁</p>

## はじめに

Blender学習16日目。前日にプリミティブで作ったブロック人形へArmatureを追加し、脚を関節から動かせるようにした。

これまでは太もも・すね・足を一つずつ選び、回転させた後に関節の位置を手作業で合わせていた。今日は骨同士を親子としてつなぎ、ポーズモード、FK、IKまで進めたことで、足先の操作だけでも脚全体を曲げられるようになった。

![FKで脚へポーズを付けたブロック人形]({{ '/images/blender_day16_development_log/fk-pose-test.webp' | relative_url }})

## Armatureで脚の骨格を作る

Armatureを追加し、編集モードで左脚へ3本のボーンを配置した。

| ボーン | 担当する部位 |
| --- | --- |
| `thigh.L` | 股関節から膝まで |
| `shin.L` | 膝から足首まで |
| `foot.L` | 足首からつま先まで |

`shin.L`は`thigh.L`の膝側から押し出し、`foot.L`は`shin.L`の足首側から押し出した。押し出しで作ると関節の点を共有したまま親子関係ができ、上位のボーンを回したときに下位も追従する。

![左脚へ作った太もも・すね・足のボーン]({{ '/images/blender_day16_development_log/bone-chain-and-parenting.webp' | relative_url }})

今回はArmatureを常に前面表示し、黒いパーツ越しでも骨を選択できるようにした。白い骨がメッシュから飛び出して見えても、操作用の表示なのでレンダーには写らない。

## 編集・ポーズ・オブジェクトモードの違い

Armatureでは、モードごとの役割を分けて考える必要がある。

| モード | 役割 |
| --- | --- |
| 編集モード | 骨の位置・長さ・接続関係など、基準となる骨格を設計する |
| ポーズモード | 基準骨格を壊さず、回転・移動・制約で姿勢を作る |
| オブジェクトモード | Armature全体をシーン内で移動・回転・拡大縮小する |

ポーズモードで付けた回転は`Alt + R`、移動は`Alt + G`で基準姿勢へ戻せる。骨格の設計と一時的なポーズが分離されているため、何度でも別の姿勢を試せる。

## 分割パーツをボーンへ割り当てる

今回の人型は、人体が一枚につながったメッシュではなく、太もも・すね・足が別々のオブジェクトになっている。そのため、自動ウェイトではなく各パーツを対応するボーンへ直接ペアレントした。

既存の親`CHR_Root`から切り替える際、そのまま別のボーンへ付けると座標の基準が変わり、パーツが離れた位置へ飛んだ。そこで一度、`Alt + P`の「親をクリア（トランスフォームを維持）」で古い親だけを外し、その後「ボーン相対」で担当ボーンへ付け直した。

この方式ではパーツがボーンへ100%固定されるため、関節周辺は滑らかに変形しない。一体化した人体を自然に曲げる段階では、各頂点へ複数ボーンの影響度を割り当てるウェイトが必要になる。

## FKで親から子へ動かす

最初に試したのはFK（Forward Kinematics／順運動学）。

- `thigh.L`を回すと、すねと足までまとめて動く
- `shin.L`を回すと、膝から下だけが動く
- `foot.L`を回すと、足先だけが動く

親から子へ順番に角度を決めるため、蹴る、座る、しゃがむといったポーズを、パーツの接続位置を直さず作れるようになった。

左脚の3本にはBlenderの命名規則`.L`を付けていたため、「アーマチュア → 対称化」だけで反対側へ複製できた。名前も`.R`へ自動変換され、親子関係を維持したまま両脚の骨格が完成した。

## IKで足先から脚全体を動かす

次はIK（Inverse Kinematics／逆運動学）を追加した。FKが股関節から順に回す方式なのに対し、IKは足首の目標地点を先に決め、そこへ届くよう太ももとすねを自動計算する。

操作用として、通常の足ボーンとは別に次の2本を作った。

- `IK_Foot.L`：足首をどこへ置くか決めるターゲット
- `IK_Knee.L`：膝をどちらへ向けて曲げるか決めるポールターゲット

`shin.L`へIKコンストレイントを追加し、次のように設定した。

![すねへ追加したIKコンストレイント]({{ '/images/blender_day16_development_log/ik-constraint-settings.webp' | relative_url }})

| 項目 | 設定 |
| --- | --- |
| ターゲット | `CHR_Armature` / `IK_Foot.L` |
| ポールターゲット | `CHR_Armature` / `IK_Knee.L` |
| チェーンの長さ | `2` |
| テールを使用 | ON |
| ストレッチ | OFF |

チェーン長`2`は、制約を付けた`shin.L`と親の`thigh.L`までを自動計算する指定。ストレッチを無効にし、人体の脚が伸び縮みせず、関節の回転だけでターゲットへ届くようにした。

## 完全な直線では膝が曲がらない

最初は`IK_Foot.L`を動かしても、太ももとすねが一本の棒のように回るだけで膝が曲がらなかった。

原因は、基準姿勢の股関節・膝・足首が完全な一直線だったこと。IK計算から見ると、膝をどちらへ曲げ始めるべきか判断できない状態になっていた。

編集モードで膝の関節点を数cmだけ前へずらし、基準骨格をごく浅い「く」の字にするとロックが外れた。ポールターゲットを置いていても、人体の肘や膝には最初からわずかな曲げ方向を与えておく方が安定する。

![膝をわずかに前へ出した練習用の2ボーンチェーン]({{ '/images/blender_day16_development_log/ik-practice-rest-bend.webp' | relative_url }})

## ポールターゲットで膝の向きを制御する

膝を曲げられるようになっても、最初は身体の後ろ側へ折れたり、横へねじれたりした。`IK_Knee.L`の位置を上面図から確認し、膝の前方へ十分に離して配置した。

![上面図で左右のポールターゲットを膝の前方へ配置]({{ '/images/blender_day16_development_log/pole-target-top-view.webp' | relative_url }})

ただし、ポールターゲットには「位置」だけでなく「ポールの角度」もある。この時点では角度を`0°`のままにしていたため、膝の曲がる平面がボーンロールに対して90°ずれていた。位置を直しただけでは、見た目は動いても意図した方向へ曲がるリグにはなっていなかった。

## 軸を揃えた片脚でIKを作り直す

一度休んだ後、メッシュを外して`thigh`と`shin`だけの練習用リグを新規ファイルで作り直した。右側面図をキャラクターの側面、画面左を身体の前方と決め、膝を最初から少し前へ曲げた。

検証では、IKとポールターゲットを一度に設定せず、役割を分けて確認した。

1. `IK_Foot`だけをターゲットに設定する
2. 足首を股関節へ近づけ、膝が曲がることを確認する
3. `IK_Knee`をポールターゲットに追加する
4. 正面図と側面図の両方で、膝の曲がる平面を確認する

ポール未設定でも、レスト姿勢の小さな曲がりを手掛かりにIKは膝を曲げられた。ただし、この状態では3D空間で膝を向ける方向が明示的に固定されていない。

![ポール未設定ではレスト姿勢の小さな曲がりを手掛かりに動く]({{ '/images/blender_day16_development_log/ik-practice-without-pole.webp' | relative_url }})

次にポールターゲットを設定すると、設定直後から正面図で脚が左へ「く」の字に折れた。`IK_Knee`は前方に置いてあるのに、膝は横へ向いている。側面図から足首を動かしても膝が曲がらないように見えたのは、実際には正面図で見える横方向へ曲がっていたためだった。

![ポール角度0°では膝の曲げ面が横へ90°ずれた]({{ '/images/blender_day16_development_log/ik-practice-wrong-pole-angle.webp' | relative_url }})

練習リグでは「ポールの角度」を`-90°`へ変更すると、正面図では脚がほぼ一直線になり、側面図では膝が`IK_Knee`の方向へ曲がるようになった。

![ポール角度を-90°へ補正し、膝が前方へ曲がる状態]({{ '/images/blender_day16_development_log/ik-practice-correct-pole-angle.webp' | relative_url }})

ここでようやく、IKにおける各コントローラーの役割を切り分けられた。

| 要素 | 決めるもの |
| --- | --- |
| `IK_Foot` | 足首の目標位置。股関節へ近づけるほど膝の曲がりが大きくなる |
| `IK_Knee` | 膝をどちらへ向けるか。脚の曲がる平面を固定する |
| ポールの角度 | ボーンロールとポール方向のずれを補正する |

ポールターゲットは膝の「曲がる量」を決めるものではない。曲がる量は股関節と足首ターゲットの距離で決まり、ポールはその曲がりを3D空間のどちらへ向けるかを決める。

また、`90°`や`-90°`という数値自体を暗記しても意味はない。必要な角度はボーンの向きやロールによって変わるため、次の2点を正面図と側面図で確認して判断する。

- 正面図で、意図せず脚が横へ折れていない
- 側面図で、膝がポールターゲット側へ曲がる

## 人形の脚へ修正を反映する

練習用リグで原因を切り分けた後、元のブロック人形へ戻った。`IK_Knee.L`を膝の前方へ置き直し、`shin.L`のポール角度を`90°`へ変更すると、左膝が横へねじれず前方へ曲がるようになった。

練習リグでは`-90°`、人形の左脚では`90°`が正解だった。これは失敗ではなく、両者のボーンロールが異なるため。数値ではなく、曲げ面を見て判断する必要がある。

![人形ではポール角度90°で膝の曲げ面を補正]({{ '/images/blender_day16_development_log/character-pole-angle-fixed.webp' | relative_url }})

左右の脚には`IK_Foot.R`と`IK_Knee.R`も作り、同じIK設定を追加した。これで左右の足首ターゲットを別々に動かし、接地や段差へ足を置くような操作ができる。

![右脚にも追加したIKの動作確認]({{ '/images/blender_day16_development_log/right-leg-ik-test.webp' | relative_url }})

## 足先の角度は回転コピーで操作する

すねへ付けたIKが制御するのは足首の位置で、`foot.L`の向きまでは自動でターゲットへ揃わなかった。そこで`foot.L`へ「回転コピー」コンストレイントを追加し、`IK_Foot.L`のXYZ回転をコピーした。

![foot.Lへ追加したIK_Foot.Lの回転コピー]({{ '/images/blender_day16_development_log/copy-rotation-settings.webp' | relative_url }})

これで`IK_Foot.L`を移動すると脚全体が曲がり、回転すると黒い足パーツの角度も変わる。右脚にも同じ設定を追加した。

回転範囲にはまだ制限を付けていないため、人間には不可能な角度まで回せる。実際の人体リグではボーンのローカル軸を整え、回転制限やIK/FK切り替えも設計することになる。

## 斜め向きの人型で混乱したこと

今日もっとも時間がかかったのはIKの設定項目ではなく、キャラクターがワールド軸に対して斜めを向いていたことだった。

テンキー`1`の正面図とキャラクター自身の正面、テンキー`3`の側面図とキャラクター自身の側面が一致していなかった。そのため、画面上で「左へ動かす」が身体にとって前・後ろ・内側のどれなのか分かりづらく、ポールターゲットの方向を何度か反対に置いてしまった。

初めてリグを作る場合は、骨を作る前に人型をワールド軸へ合わせておく方がよい。

- 左右：X軸
- 前後：Y軸
- 上下：Z軸
- テンキー`1`：真正面
- テンキー`3`：真横

この状態なら、左右対称化、膝の初期角度、ポールターゲットの前方配置を、正投影だけで確認しやすい。

## 骨へメッシュの向きを合わせる

IKの骨格を修正した後も、太ももやすねの黒いメッシュはボーンに対して斜めに取り付いたままだった。骨の関節位置とIKの動作が正しいことを優先し、今度は骨を見た目へ無理に合わせず、メッシュ側の位置と回転を調整した。

ポーズを初期化してオブジェクトモードへ戻り、各パーツを側面図と正面図から`R`と`G`で合わせた。

- 太ももの上端を股関節、下端を膝へ合わせる
- すねの上端を膝、下端を足首へ合わせる
- メッシュの長手方向へ担当ボーンを通す
- 足パーツを`foot.L`／`foot.R`へ合わせる

既に「ボーン相対」でペアレントしてあるため、取り付け角度を直した後もIKへそのまま追従した。これで骨とメッシュの対応が見やすくなり、両脚を大きく曲げても各パーツが担当ボーンに沿って動くようになった。

![ボーンへ太もも・すね・足のメッシュを合わせた完成状態]({{ '/images/blender_day16_development_log/character-rig-mesh-aligned.webp' | relative_url }})

## 今日覚えたこと

- Armatureの編集モードは骨格設計、ポーズモードは姿勢作りに使う
- 押し出したボーンは関節を共有した親子チェーンになる
- 分割された硬いパーツは、対応ボーンへ直接ペアレントして動かせる
- FKは親から子へ順番に回転させる
- IKは末端の目標位置から親側の回転を逆算する
- IKチェーンを完全な直線にせず、膝へ小さな初期角度を付ける
- `IK_Foot`は曲がる量、ポールターゲットは膝の曲がる平面と向きを制御する
- ポールターゲットの位置が正しくても、ポール角度がずれると膝は横方向へ曲がる
- ポール角度は数値を暗記せず、正面図と側面図から曲げ面を確認する
- 足先の角度は回転コピーでIKターゲットへ合わせられる
- 初めてのリグでは、人型の正面とワールド軸を揃えると混乱が少ない
- 骨の動作が正しければ、見た目のズレはメッシュ側を骨へ合わせて修正する

## 振り返り

今日は、パーツを一つずつ直接回す段階から、骨格を操作してポーズを作る段階へ進んだ。FKを試した時点で動きの幅が大きく増え、IKでは足先を一つ動かすだけで太ももとすねが追従する面白さを体験できた。

一方、最初の作業を終えた時点ではIKを理解できたとは言いにくかった。直線チェーンのロック、ポールターゲットの前後、ワールド軸と身体方向、さらにポール角度のずれが重なり、後半はかなり混乱した。

そこで軸を揃えた片脚だけのリグを最初から作り直し、IKとポールターゲットを別々に検証した。結果、原因は`IK_Knee`の位置だけではなく、ボーンロールに対してポール角度が90°ずれていたことだと特定できた。

最終的には元の人形でも左右の脚を補正し、メッシュの向きまで骨へ合わせられた。単に手順をなぞって動かすところから、症状を正面・側面で観察し、IKの「曲がる量」と「曲がる方向」を切り分けて直すところまで進めたのが、今日一番の収穫だった。

## 次回

次は、今回補正した脚リグを使ってキーフレームによる簡単なアニメーションへ進む。最終的には一体化した人体メッシュとウェイトへ進み、関節周辺が滑らかに変形する仕組みも学びたい。
